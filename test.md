# DEMANDOPS AI — FINAL FULL-SYSTEM AUDIT & FIX

Perform a complete audit of the existing DemandOps AI project.

Do NOT rebuild the application.

First inspect the current implementation, then identify gaps, then fix only what is required.

The final system must implement the architecture below exactly.

---

# 1. CORE ARCHITECTURE

The system is:

CUSTOMER INPUT

→ Region / Store / Products / Current Inventory / Forecast Horizon

→ BACKEND LOADS HISTORICAL SALES DATASET

→ BACKEND FILTERS DATA FOR REGION / STORE / PRODUCT

→ BACKEND APPLIES FORECASTING ALGORITHMS

→ TREND / DEMAND ANALYSIS

→ DETERMINISTIC FORECAST

→ INVENTORY CALCULATIONS

→ RISK ANALYSIS

→ BEDROCK MANTLE AI REASONING

→ AI RECOMMENDATION

→ HUMAN EMPLOYEE REVIEW

→ MODIFY / APPROVE / REJECT

→ FINAL DECISION

→ AUDIT TRAIL

## CRITICAL PRINCIPLE

Historical sales are **NOT customer input**.

Historical sales are **backend-owned data**.

The customer must NOT upload historical sales.

The customer must NOT select or manually enter historical sales.

The frontend must NOT send historical sales rows to the backend.

The backend is responsible for finding and applying the appropriate historical data.

# 5. HISTORICAL DATA PROCESSING

The backend must:

1. Load historical dataset.
2. Filter relevant records.
3. Group historical demand by product/store/region.
4. Sort by date.
5. Validate data.
6. Remove/handle invalid records.
7. Calculate historical demand statistics.
8. Detect trends.
9. Apply forecasting algorithm.
10. Generate forecast.
11. Calculate confidence.

Do not simply select a precomputed forecast from the dataset.

The historical dataset is the **raw demand history**.

The backend must actually process it.

---

# 6. TREND ANALYSIS

The backend should analyze historical demand for each product.

At minimum determine useful demand characteristics such as:

* average demand
* recent demand
* trend direction
* growth/decline
* volatility
* recent moving average
* demand variability

If the implementation supports seasonality, use it where sufficient data exists.

Example:

Rice historical demand:

Day 1: 8

Day 2: 9

Day 3: 10

Day 4: 11

Day 5: 12

The system should recognize the increasing demand pattern rather than simply averaging blindly.

The exact forecasting algorithm can remain deterministic and explainable.

---

# 7. FORECASTING

Forecasting must remain deterministic.

The LLM must NOT calculate the forecast.

The backend should use the historical data and configured forecast horizon.

For example:

Forecast horizon = 14 days

Historical data → trend analysis → forecasting algorithm → 14-day forecast.

For every requested product persist:

* product_id
* store_id
* forecast_horizon
* forecast_quantity
* average_daily_demand
* trend
* volatility if available
* forecast_confidence.

---

# 8. FORECAST CONFIDENCE

Confidence should be calculated by the backend based on meaningful characteristics such as:

* amount of historical data
* demand consistency
* volatility
* data quality
* model reliability.

Do not let the LLM invent the base forecast confidence.

The AI may interpret the confidence later.
